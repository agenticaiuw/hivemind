## Capabilities it proposed

### "“What am I agreeing to here?” While I have a private webpage open, read the relevant terms, deadlines, fees, and commitments; compare them with my Calendar and Reminders; tell me the important conflicts or risks through the pendant; and prepare any suggested reminders without submitting or accepting anything."
- **useful because:** Today the owner must manually copy terms from authenticated portals into another tool and remember to check their calendar. This would turn a private webpage into an immediate, spoken decision brief grounded in the owner’s actual schedule, while preserving control over acceptance and reminder creation.
- **path:** browser-extension → mac-planner → relay-realtime → pendant → faculty-perception → faculty-judgement
- **model tier:** Use a cheaper background/text model for page extraction and structured obligation detection; use the realtime model only to answer the owner’s follow-up questions and deliver the short spoken summary. Mac-side Calendar/Reminders APIs provide deterministic conflict checks rather than spending model tokens.
- **latency:** Initial extraction and schedule comparison within 10–20 seconds after the owner asks; spoken first answer under 3 seconds once the structured page brief is ready. Follow-up questions should feel conversational.
- **cost:** Roughly one small text-model call per page plus a few deterministic Calendar/Reminders queries; realtime cost only for the voice exchange. Dominant cost is sending selected authenticated-page text for analysis, so cap extraction to relevant sections and retain no raw page copy beyond the task.
- **security:** Authenticated page content must remain on the Mac/browser path unless the owner’s relay policy permits selected excerpts; redact account numbers and unrelated page regions before analysis. Calendar and reminder data are sensitive and should be projected as only the date/title conflicts needed. Never click Accept, Agree, Purchase, Send, or Create without a separate explicit owner request; show quoted source evidence and proposed reminder text first.
- **missing:** A browser action that captures the current authenticated tab with selected semantic sections and provenance, rather than relying on a stale URL or full-page dump; A local structured obligation/deadline extractor that can pass only minimized excerpts to the planner; A Calendar/Reminders conflict-query adapter callable from the browser task; A pendant response mode for short sourced briefs with expandable evidence and proposed reminder review; Cross-surface privacy routing so raw page contents stay local while only the minimum derived facts reach relay-realtime


## Changes it proposed to its own stack

### `browser-harness` — Add an offline-aware browser command circuit breaker and recovery journal. Before enqueueing or waiting on any browser action, evaluate the extension heartbeat age and tab availability; when stale, atomically move pending commands into a quarantined state with their idempotency key, target session/tab, and remaining intent, coalesce duplicate read/watch retries, and return a typed `browser_unavailable` result with the last-known URL/title and a concise reconnect instruction. On the next valid Safari heartbeat, revalidate session/tab affinity, resume only safe idempotent reads automatically, and expose failed or mutation-intent steps for planner continuation without replaying them. Emit one outage/recovery event to the relay and pendant instead of repeated 45-second timeout noise.
- **owner gets:** When Safari is closed, asleep, or the extension disconnects, the owner gets an immediate honest status instead of waiting through repeated 45-second failures; reopening Safari resumes page monitoring without duplicate reads or silently lost work. Private sessions remain private, and a pending form-fill is preserved rather than accidentally replayed.
- effort: Medium: heartbeat-age state machine and durable quarantine records in browserBridge/browserSessions, deduplication and resume worker, typed relay/pendant event, plus tests for disconnect/reconnect and stale tab IDs.  ·  risk: A heartbeat can appear healthy while a tab is actually gone, or a quarantined command can be resumed against the wrong tab. Require session/tab revalidation and content-addressed idempotency before reads; invalidate and surface the step when identity changes. Keep mutation-intent commands quarantined until the planner explicitly continues them; recover by showing the saved intent and evidence.
- cost: Negligible API cost; a small local JSON/D1 journal (roughly a few KB per outage) and one relay event per transition. This reduces wasted browser and model time from timeout storms.  ·  latency: Unavailable actions return in under 1 second; normal connected actions add only a heartbeat lookup (tens of ms). Recovery reads resume on the next poll rather than waiting for a 45-second lease expiry.
- security: No page content leaves the Mac during outage signaling; only device/session identifiers, status, and last-known metadata go to the relay. Preserve existing private-session affinity and redact URLs/query strings where configured.
- depends on: A durable browser job runner and resumable result stream (chg-16bc5dee); Existing request IDs/idempotency and tab/session affinity (chg-14accc01); Safari extension heartbeat/status and browserSessions persistence

### `integration` — Create a local authenticated-page evidence compiler between the Safari bridge and the planner. It should accept the active tab’s DOM/text, identify obligation-like regions (dates, amounts, renewal/cancellation language, required actions), produce a compact typed record with exact source snippets and locators, and emit a redaction manifest proving which page regions were excluded. Calendar/Reminders conflict queries should consume that typed record locally; relay-realtime should receive only the derived brief and cited snippets, never the untouched page. Keep the raw capture ephemeral and destroy it after the task receipt is written.
- **owner gets:** The owner can ask what a private page means and get a useful answer without exporting an entire logged-in account page or manually copying text. Important deadlines can be compared against their schedule accurately, while unrelated private data stays on the Mac.
- effort: High: DOM-region extraction and obligation schema, local redaction and ephemeral storage, provenance-preserving citations, deterministic Calendar/Reminders join, and a pendant-readable evidence response format.  ·  risk: Semantic extraction may miss a clause or mistake promotional text for a commitment. Return confidence and quote the source; never claim completeness. If provenance or redaction validation fails, return the page locally for review rather than sending it upstream. Recover by retaining only the typed record and re-running extraction on the active tab.
- cost: One local extraction pass plus a small text-model call only when local heuristics are insufficient; much lower relay token cost than forwarding full pages. Ephemeral raw capture uses local memory/disk for seconds, then is deleted.  ·  latency: About 1–5 seconds locally for ordinary pages; complex pages may add 5–15 seconds for model-assisted extraction. Subsequent Calendar/Reminders checks are deterministic and near-instant.
- security: Meaningfully reduces data exposure: raw authenticated content remains on the Mac, relay receives only minimized evidence. Requires strict logs that store hashes/locators rather than raw page text and careful redaction of account identifiers.
- depends on: A functioning browser command enqueue path and live Safari tab capture; A typed evidence/provenance result contract for browser actions; Local Calendar/Reminders query integration; Relay support for privacy-labeled derived facts
