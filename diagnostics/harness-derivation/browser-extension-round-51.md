## Capabilities it proposed

### "“What am I looking at right now?” — then ask a follow-up about the page without copying anything into chat."
- **useful because:** The browser extension is the only node with the owner's authenticated page, while the pendant is the only node that can answer hands-free. This creates a private, low-friction way to interrogate the current tab: the browser extracts only the relevant regions, the Mac summarizes locally, and the pendant receives an answer with exact page/section citations. Public cross-checks can be fetched by the relay, but credentials and raw page text never leave the Mac unless the owner explicitly asks.
- **path:** browser-extension → mac-planner → relay-realtime → pendant → unified
- **model tier:** Use a cheap local Mac model for DOM cleanup, relevance filtering, and citation indexing; use realtime only to resolve the spoken question and compose the short spoken answer. Use the relay's cheaper background tier for optional public fact cross-checks.
- **latency:** 1–2 seconds after the question when a tab snapshot is warm; up to 5 seconds for a fresh authenticated extraction or public cross-check. Cache a short-lived, tab-bound semantic snapshot and invalidate it on navigation.
- **cost:** Usually one realtime turn plus a small local summarization call; roughly $0.002–$0.02 per question depending on whether a public cross-check is requested. The dominant cost is re-sending page context, so local extraction and bounded snippets are important.
- **security:** Raw authenticated DOM, cookies, form values, and screenshots remain on the Mac. Send the relay only the spoken question, selected snippets, and citation metadata; redact secrets, tokens, payment details, and hidden fields before any model call. Never include editable form fields in the warm snapshot. A private physical gesture (long-press) should be required to capture a fresh page snapshot; the owner can say 'forget this page' to erase it.
- **missing:** A browser-extension command for a tab-scoped semantic snapshot that excludes inputs/hidden fields and returns DOM locators plus text hashes; A local Mac redaction/relevance service and short-lived encrypted snapshot cache; A pendant gesture/voice intent that binds the next question to the current Safari tab; A citation-aware response contract linking each spoken claim to URL, tab, timestamp, and section; A relay route for optional public cross-checks that accepts only redacted snippets and expires them quickly

### "“Watch my important logged-in pages, but interrupt me only when something is urgent for what I’m doing right now; otherwise queue it for the next natural pause.”"
- **useful because:** A meaningful page change is not automatically worth interrupting the owner. Safari can see private alerts, the Mac can see the current app and calendar context, the relay can rank urgency, and the pendant can deliver a brief interruption or defer it. This gives the owner attention-aware automation rather than another noisy page-watch feed.
- **path:** browser-extension → mac-planner → relay-realtime → pendant → unified
- **model tier:** Use a cheap background model for page-change classification and urgency scoring, deterministic Mac signals for active app/calendar/focus state, and realtime only for an actual pendant interruption and the owner's follow-up. No expensive model should run merely because a page was polled.
- **latency:** Detect and classify within 1–3 minutes of a scheduled page check; deliver an interruption within 5 seconds for a high-confidence urgent event. Nonurgent events should appear in a queued digest at the next detected pause.
- **cost:** Low: scheduled extraction plus a small classification call per changed page, typically under $0.01 per change; realtime cost is limited to actual spoken interruptions. The main cost is authenticated polling and context refresh, not conversation.
- **security:** The Mac must keep raw authenticated page content local and send the relay only a redacted event summary, urgency class, and citation. Calendar and active-app context are sensitive and need coarse categories rather than raw titles by default. Never interrupt during an owner-defined focus, driving, sleep, or private mode; never click, reply, or submit automatically.
- **missing:** An event stream from authenticated browser watches rather than polling results only; A Mac-local attention-state service combining Focus mode, active app, calendar occupancy, audio state, and optional pendant motion/presence; A durable urgency/defer queue with deduplication, quiet hours, escalation, and owner-tunable interruption budgets; A relay protocol for short-lived redacted browser events with citations and delivery receipts; Pendant controls for defer, mute this source, and mark urgent without opening the browser


## Changes it proposed to its own stack

### `browser-harness` — Add a tab-scoped 'private context lease' spanning Safari extension, Mac agent, and relay: on a pendant long-press, capture the active tab's readable DOM while excluding inputs, hidden elements, cookies, and screenshots; normalize it locally into expiring chunks with URL/title/DOM locator/text hash; answer follow-up questions against those chunks; send only selected redacted snippets and citation IDs to the relay; revoke and securely erase the lease on navigation, timeout, explicit 'forget', or Safari closing. Return typed claims with source locators so the pendant answer can say where each claim came from.
- **owner gets:** They can ask about the authenticated page in front of them without speaking sensitive page contents aloud, pasting them into chat, or trusting an uncited summary. It makes the wearable useful precisely where public web tools cannot reach and keeps private data on the owner's Mac by default.
- effort: Medium-high: extension extraction and navigation invalidation, Mac encrypted in-memory/disk cache, redaction and lease lifecycle, a typed claim/citation response, and pendant intent wiring; add end-to-end tests for Gmail-like pages, forms, and navigation races.  ·  risk: A bad extractor or redactor could omit important context or leak a secret. Recover by fail-closed redaction, visible lease state, no screenshots/forms by default, bounded TTL, audit receipt, and a fallback that says the page could not be safely read rather than sending raw DOM. Navigation races must invalidate old tab IDs and hashes.
- cost: Small local CPU/storage cost; one compact model call for local extraction/relevance and occasional realtime call for spoken synthesis. Typical API cost about $0.002–$0.02/question; no new hardware required.  ·  latency: Warm lease answers in ~1–2 seconds; fresh capture/relevance in ~3–5 seconds. Navigation invalidation is immediate.
- security: Improves privacy by making the Mac the data boundary, using least-data snippets, expiring encrypted leases, and preserving provenance. It does not grant new website permissions or submit forms.
- depends on: Working browser command enqueue/result path (currently Safari is offline and has no tab); Typed browser extraction result with locators and tab affinity; Mac-local redaction/relevance service; Pendant long-press/voice intent and lease status feedback

### `interaction` — Create an attention-arbitration bus between authenticated browser events, Mac presence/context signals, relay prioritization, and pendant delivery. Each event receives a source citation, urgency/confidence, expiry, deduplication key, and delivery policy. The arbiter combines Focus mode, calendar occupancy, active app, audio state, sleep/quiet hours, and recent pendant interactions; it either delivers a one-sentence interruption, queues a digest, or suppresses the event. Add explicit pendant actions for defer, mute-source, and escalate, with an auditable delivery receipt.
- **owner gets:** Important private-site changes reach the owner at a useful moment instead of becoming either constant interruptions or an unread pile. The system adapts to what the owner is doing without taking actions on their behalf.
- effort: High: define the event schema and broker, integrate browser watch results and Mac context, implement durable queue/escalation logic, pendant controls, and replayable tests for focus, sleep, duplicate, and stale-event cases.  ·  risk: Incorrect urgency or presence inference could interrupt at a bad time or bury something important. Recover with conservative defaults, per-source budgets, visible queued history, expiry notices, and an always-available 'show suppressed items' command. No external mutation is performed by the arbiter.
- cost: Small persistent queue and local classification cost; approximately $0.001–$0.01 per changed event, with realtime spend only for delivered spoken alerts. No hardware purchase required.  ·  latency: Sub-second local arbitration after an event arrives; browser detection remains bounded by the configured watch cadence. High-urgency delivery target is under five seconds after classification.
- security: Raw page contents stay on the Mac. Relay receives redacted event summaries and citations. Context signals are minimized to coarse state and expire quickly; delivery receipts contain no page secrets.
- depends on: Authenticated browser watch event stream; Mac-local attention-state/context service; Durable deduplicating event queue; Pendant defer/mute/escalate controls; Redacted browser-event relay contract
