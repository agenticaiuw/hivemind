## Capabilities it proposed

### "“Compare the figures in this logged-in web dashboard with my local spreadsheet or notes, tell me exactly what disagrees, and prepare the corrections without submitting or sending anything.”"
- **useful because:** This combines the browser’s unique access to private authenticated data with the Mac’s access to local files. Today each surface can inspect its own side, but neither can produce a sourced reconciliation, preserve evidence, and stage a safe correction for review.
- **path:** browser-extension: open the already-authenticated Safari dashboard, extract the requested records with URL/tab/timestamp evidence, and stop before any submit/send control → mac-planner: locate and parse the named local spreadsheet/notes, normalize dates, currencies, identifiers, and totals, and stage a patch or draft artifact → relay-realtime: ask one clarifying question when the matching key or conflict policy is ambiguous, then speak a concise discrepancy summary through the pendant → unified: reconcile both evidence sets, rank material discrepancies, and present before/after values plus the exact staged edits
- **model tier:** Use the ordinary planner/cheap background model for extraction, normalization, matching, and diffing; reserve realtime only for the pendant clarification and final spoken summary. No expensive model call is needed for stable tabular comparisons.
- **latency:** Initial authenticated read and local-file scan: 10–30 seconds depending on page size. Matching/diffing: under 5 seconds. Draft artifact: another 2–10 seconds. The owner can review while the browser session remains open; no irreversible action is taken automatically.
- **cost:** Usually low: one planner call plus bounded browser extraction and local parsing; roughly $0.01–$0.08 per reconciliation, dominated by page text and spreadsheet context rather than model latency. Repeated unchanged records should be cached by source fingerprint.
- **security:** Private dashboard text and selected local-file rows leave the Mac only to the relay/model for reconciliation; do not upload whole files when selected ranges suffice. Store source URL, tab ID, timestamps, and hashes rather than credentials. Mask secrets and unrelated rows. Never click submit, send, approve, or purchase; show the exact proposed changes and destination first.
- **missing:** Safari extension must heartbeat online and have an attached tab; current live state is offline with no tab and 5 pending commands; Durable cross-source reconciliation schema with typed keys, normalization rules, confidence, and provenance; Local spreadsheet/notes reader that can return selected ranges and produce a reviewable patch artifact; A browser result contract carrying stable extracted fields plus URL/tab/timestamp and a way to keep the authenticated session bound

### "“Audit where my personal data is stored across the logged-in sites I use and on my Mac, show me what each copy contains and how long it has been there, then prepare export or deletion requests without sending them.”"
- **useful because:** No current surface can answer the owner’s real privacy question end to end. The browser can reach account settings behind existing logins, while the Mac can inventory local downloads, exports, caches, and notes; combining them would reveal forgotten copies and produce concrete, reviewable next steps rather than generic privacy advice.
- **path:** browser-extension: inspect only explicitly selected authenticated account/privacy pages, collect data-category, retention, export and deletion options with URL/tab/timestamp evidence → mac-planner: inventory owner-selected folders and app data locations, classify likely personal-data exports and duplicates, and generate a local manifest without uploading raw files → relay-realtime: explain the audit in a short spoken summary and ask for scope choices such as which services, folders, or data categories to include → unified: correlate account data categories with local copies, flag uncertainty and sensitive findings, and prepare exact unsent export/deletion drafts for review
- **model tier:** Use a cheaper background model for inventory classification, deduplication, and policy-page extraction; use realtime only for scope clarification and the final pendant summary. A stronger model is needed only for ambiguous privacy-policy language, not every file.
- **latency:** A scoped audit of 3–5 services and selected folders should complete in 1–3 minutes, with progress updates and resumability. Initial scope confirmation should take under 10 seconds. Draft generation follows within 15 seconds after the last source is read.
- **cost:** Approximately $0.05–$0.30 per scoped audit, dominated by authenticated policy pages and compact file metadata; raw file contents should remain local unless the owner explicitly includes a file for inspection.
- **security:** This workflow itself handles highly sensitive information. Require explicit scope before scanning, keep raw files on the Mac, redact account identifiers and secrets from model context, store only metadata/hashes by default, and never click final delete/export confirmation or send a request. Every finding needs source URL or local path, timestamp, and confidence so the owner can remove individual sources from the report.
- **missing:** A privacy-audit job and manifest schema for account data categories, local artifacts, retention, and evidence; A Mac metadata-only inventory reader with configurable folder/app boundaries and local hashing; A browser extraction recipe for account privacy/data-export pages that can traverse multiple chosen services while preserving session and provenance; A review UI or artifact that groups each finding into retain, export, delete, or uncertain and renders unsent request drafts; A durable redaction and deletion policy for audit manifests and completed artifacts


## Changes it proposed to its own stack

### `integration` — Add a Cross-Source Reconciliation job type between browserBridge and the Mac agent. It accepts two source descriptors (authenticated tab extraction recipe and local file/range), emits normalized typed records with provenance, joins on declared or inferred keys, computes materiality/confidence, and writes a review artifact containing before/after values and an unapplied patch. Browser extraction must carry deviceId/tabId, URL, title, extraction timestamp, selector/region, and content hash; local extraction must carry file path, sheet/range or note heading, mtime, and hash. Reuse the existing job/receipt records and browser session binding, but add a deterministic dry-run result and resume cursor so a dropped extension does not lose the diff.
- **owner gets:** They can ask one sentence and get a trustworthy answer about whether their private dashboard and local records agree, with the exact corrections ready to review instead of manually copying between windows or risking an accidental submission.
- effort: Medium: a typed job schema, two bounded extractors, normalization/join library, provenance-bearing result contract, and a review-artifact writer. Add fixture tests for currency/date/time-zone and duplicate-key conflicts, plus one Safari integration test when the extension is online.  ·  risk: A bad inferred join could create false discrepancies or suggest an incorrect correction. Default to explicit owner-provided keys, label uncertain matches, and never apply the patch. If the browser drops, retain partial source evidence and mark the job incomplete rather than claiming agreement; recovery resumes from the source fingerprint/cursor.
- cost: Low incremental API cost because extraction is bounded and normalized before model comparison; storage is small JSON/CSV diffs plus hashes. No new hardware cost.  ·  latency: Adds roughly 1–5 seconds for normalization and join after each source read; avoids repeated model context by comparing compact typed records.
- security: More structured handling of private data is safer than sending whole pages/files. Keep credentials and unrelated rows local, redact configured sensitive columns, and retain only hashes/provenance plus the selected values in the review artifact.
- depends on: A live Safari extension heartbeat and attached tab (currently absent: /browser/status reports offline, no tab, 5 pending commands); Durable browser command queue/session affinity already represented by chg-14accc01, with typed extraction results actually implemented; A local selected-range/file reader on mac-planner rather than whole-file shell dumps; A shared provenance/context projection so the model receives only matched records, not full page and file contents

### `integration` — Add a privacy-audit pipeline that runs as a durable, scoped manifest job: browser account adapters emit typed data-category/retention/export/delete evidence; a Mac-local scanner emits metadata, hashes, path, app, and mtime without file contents; a correlator joins them, assigns confidence and retention recommendations, and renders an owner-reviewable report with unsent request drafts. Give every source a revocable scope token, per-item retention, and a one-click purge of the audit artifact itself.
- **owner gets:** The owner gets a concrete map of forgotten personal-data copies and can act on it safely, instead of having to visit each account and search their Mac manually or trust an untraceable AI summary.
- effort: High: adapter contracts for privacy pages, a sandboxed metadata scanner, redaction/classification, durable resumable jobs, report rendering, and deletion tests. Start with two common account providers and user-selected folders, then expand.  ·  risk: False classification could recommend deleting something needed for work or misread a provider’s retention policy. Mark uncertainty, preserve citations and local paths, require review for each deletion/export draft, and never execute the final provider action. If a session expires, retain no credentials and mark that source incomplete.
- cost: Moderate engineering cost; low recurring API cost because metadata and hashes are compact. Local hashing adds CPU/disk reads but no new hardware or cloud storage requirement.  ·  latency: Initial scan may take 30–120 seconds for selected folders and several authenticated pages; incremental audits can use mtimes/content hashes and finish in seconds.
- security: Improves security by defaulting to metadata-only and explicit scope, but creates a sensitive manifest. Encrypt it at rest, keep raw files local, redact identifiers before model calls, expire artifacts automatically, and log every access.
- depends on: A durable cross-surface job runner with pause/resume and partial-source status; Authenticated browser adapter/result contracts that preserve URL, tab, timestamp, and evidence snippet; A local Mac metadata scanner that never uploads raw file contents by default; A privacy-specific retention, redaction, and artifact purge policy
