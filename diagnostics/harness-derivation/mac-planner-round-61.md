## Capabilities it proposed

### "“If something I ask you to do is blocked by a Mac or browser permission, tell me exactly what to enable, open the right settings page, and continue the job automatically once it’s fixed.”"
- **useful because:** Today the bridge reports online while Accessibility and Screen Recording are false, so UI actions can claim success while doing nothing and three browser commands are stranded offline. This turns a silent failure into a guided, resumable interaction: the pendant explains the one required fix, the Mac opens the relevant pane, and the relay resumes only the checkpointed step after a fresh health check.
- **path:** pendant → relay → mac-bridge → browser → dashboard
- **model tier:** Use a deterministic permission classifier and cheap background model for diagnostics/checkpoint summaries; reserve realtime only for the short spoken explanation and the owner's follow-up. No vision model is needed for the permission flow.
- **latency:** Detect within 1 second of a failed preflight; open System Settings within 2 seconds; poll permission state every 3 seconds while the user is in Settings; resume within 5 seconds after the grant. Browser reconnection can take up to 30 seconds with visible pending-job status.
- **cost:** About $0.001–$0.01 per incident, dominated by a short spoken response or fallback TTS; permission checks, polling, and checkpoint storage are local/relay operations.
- **security:** Never infer or silently change permissions. Open only the exact macOS Privacy & Security pane and require the user to toggle access themselves. Do not transmit screenshots, page contents, or credentials; report only boolean permission state and the failed action class. Resume must be idempotent and revalidate tab/session identity before browser steps.
- **missing:** A real read-only Mac preflight/diagnostics implementation (the granted inspection schema currently returns no implementation) exposing Accessibility, Screen Recording, browser-bridge heartbeat, and input reachability; A durable job checkpoint state machine that marks the exact failed action and prevents replay of completed mutations; macOS deep links for Accessibility and Screen Recording settings plus a permission-change watcher/heartbeat; Browser extension heartbeat recovery that drains the three pending commands only after the extension is online and tab affinity is confirmed; Pendant/relay event contract for concise permission prompts and completion receipts

### "“Even if my Mac or browser is offline, remember this browser task, tell me it’s queued, and do it when the right tab comes back—unless the page or request has gone stale.”"
- **useful because:** The browser is currently offline with three pending commands, while the relay remains reachable. The pendant should not force the owner to repeat a task or falsely claim completion. A durable, expiry-aware queue would accept intent now, wait for the browser heartbeat, reattach only to the named session/tab, and ask again when facts have materially changed.
- **path:** pendant → relay → mac-bridge → browser → dashboard
- **model tier:** Cheap background model for intent normalization, stale-risk classification, and later result summarization; realtime only for the immediate spoken queue receipt or a conflict question.
- **latency:** Immediate spoken queued receipt in under 2 seconds. Resume within 10 seconds of a healthy browser heartbeat. If stale or conflicting, notify within 5 seconds and leave the task paused rather than retrying blindly.
- **cost:** Roughly $0.001–$0.02 per queued task, mostly for intent normalization and final summary; heartbeats, queue storage, and tab checks are infrastructure operations.
- **security:** Persist only the minimum intent and tab/session reference, encrypted at rest; never persist passwords or page bodies by default. Revalidate URL origin, tab identity, authentication state, and extracted preconditions at execution time. Never submit irreversible actions after an offline interval without renewed confirmation; drafts and read-only actions may proceed according to owner policy.
- **missing:** A relay durable intent queue with TTL, dependency/precondition fields, idempotency key, and explicit states queued/waiting/stale/conflict/completed; A browser heartbeat/reconnect protocol that reports authenticated session and tab affinity without exposing page content; A pre-execution semantic diff that compares saved preconditions with the live page and routes conflicts to the pendant; A unified receipt format shared by relay, Mac, and browser, including queued time, resumed time, skipped steps, and evidence links; Dashboard controls to edit, cancel, reprioritize, or approve stale queued work

### "“When I come back to my Mac, tell me what changed across my pendant, desktop, and browser while I was away, why it changed, and what still needs me—with each claim linked to the original event or page.”"
- **useful because:** Today activity is split across relay jobs, Mac actions, browser sessions, and spoken interactions. The owner cannot reliably reconstruct whether an item was merely discussed, actually changed, or failed halfway through. A cross-surface causal timeline would give them one trustworthy return point: event, agent decision, concrete effect, evidence, and unresolved consequence, rather than another ungrounded summary or a raw action log.
- **path:** pendant → relay → mac-bridge → browser → dashboard
- **model tier:** Use deterministic event correlation and a small background model to cluster events and classify unresolved consequences; use the realtime model only when the owner asks for the spoken return brief. Store summaries rather than repeatedly sending the full event history.
- **latency:** Capture events within 2 seconds; produce a return brief in under 5 seconds for a normal workday and under 15 seconds for a multi-day gap. Drill-down evidence can load progressively without delaying the headline.
- **cost:** Approximately $0.005–$0.05 per return brief, dominated by background summarization; event ingestion, hashing, correlation, and local Mac records are inexpensive. Realtime cost occurs only for an interactive spoken follow-up.
- **security:** Keep sensitive page text, mail bodies, and audio local or encrypted with short retention; transmit typed event metadata and evidence hashes by default. Separate owner-visible history from model context, support per-source exclusion and deletion, and label inferred causality clearly. Never imply that a conversation caused a mutation unless the event chain proves it.
- **missing:** A shared append-only event envelope emitted by relay, pendant, Mac, and browser with event ID, actor, timestamp, correlation ID, surface, effect, and sensitivity class; A causal-linking service that joins one owner request to plans, retries, Mac/browser actions, receipts, and resulting observations without duplicating events; Evidence pointers that remain valid after tabs close or files move, using content hashes and bounded local snapshots rather than unrestricted retention; A return-state API and dashboard timeline with filters for changed, failed, awaiting-owner, inferred, and excluded sources; A privacy/retention control plane allowing the owner to disable a source, erase its history, or keep only hashes and outcome metadata


## Changes it proposed to its own stack

### `integration` — Add a cross-surface causal event ledger and return-state compiler. Every relay turn, pendant event, Mac plan/action, browser command, observation, retry, and receipt receives a correlation ID and typed outcome. The compiler materializes a compact per-owner-away-window graph of changed artifacts, failed or partial work, unresolved decisions, and evidence pointers; it exposes both a spoken return brief and a dashboard drill-down. It must deduplicate retries, distinguish observed facts from inferred causal links, and support source-level retention and erasure.
- **owner gets:** When the owner returns, they can know what actually happened—not just what an agent said it would do—and immediately see what still requires their attention, with proof attached to each claim.

- security: Improves auditability but creates a sensitive activity graph. Encrypt records, minimize page/audio content, use hashes and local evidence pointers by default, enforce TTLs and per-source opt-out, and clearly mark inferred links.
- depends on: A versioned shared event envelope and correlation-ID contract; Durable encrypted storage with retention and deletion semantics; Evidence-pointer/hash support in Mac and browser harnesses; Relay endpoint for return-state queries and spoken summaries
