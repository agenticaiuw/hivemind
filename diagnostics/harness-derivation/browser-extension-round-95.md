## Capabilities it proposed

### "“If Safari is unavailable, remember the private-page task and resume it when my browser reconnects—tell me if anything changed, and never run the same step twice.”"
- **useful because:** Today a private browser request can sit in nine stale commands or consume a 45-second timeout, then fail with no reliable handoff. This would let the owner leave the Mac or close Safari without losing the request, while preserving authenticated-page access that the relay cannot provide. It would resume only the unfinished read/extract work, report the exact last completed step, and avoid duplicate navigation or mutations.
- **path:** pendant → relay → mac-planner → browser-extension → dashboard
- **model tier:** Use the cheap background model for queue bookkeeping, retry classification, and change comparison; use realtime only to acknowledge the owner's request and speak the final concise update. Browser extraction can invoke the stronger model only when page structure or semantic change is ambiguous.
- **latency:** Acknowledge in under 2 seconds; detect bridge absence within 10 seconds instead of waiting 45 seconds; resume within one polling interval (up to 30 seconds) after Safari heartbeat. No repeated 45-second blocking waits.
- **cost:** About $0.005–$0.03 per resumed read, dominated by page extraction and semantic diff; heartbeat/lease bookkeeping is negligible. No relay Browser Run spend for owner-private pages.
- **security:** Private URLs and extracted text remain on the owner's Mac/relay path and must not be failed over to public Browser Run. Persist only encrypted job metadata and evidence hashes by default, with short-lived page text. Read-only steps may resume automatically; if the task reaches typing, sending, submitting, or purchasing, stop and present the exact pending action rather than replaying it. Every step needs an idempotency key and tab/session binding.
- **missing:** A device heartbeat lease with explicit device identity and reconnect generation; Safari currently disappears from /browser/status while nine commands remain pending.; A circuit breaker that marks queued commands stale after lease expiry, quarantines them, and emits a reconnectable job rather than allowing blind 45-second waits.; Durable per-step checkpoint storage and replay classification (completed, safely retryable, or requires owner review), plus a single result stream to the pendant and dashboard.; A Mac-side reconnect hint/health action so the owner can be told Safari is not polling without treating home-chrome as a substitute.

### "“While I’m looking at a private webpage, let me ask the pendant questions about this exact tab; keep the context only while I’m there, and forget it when I leave.”"
- **useful because:** Today the owner must explicitly initiate a browser extraction and cannot have a natural, hands-free conversation anchored to the page already in front of them. This would make the pendant a private-page companion: they could ask “what does this fee mean?”, “which date is listed?”, or “compare these two visible options” without copying URLs or exposing the page to a general web search. The context would be intentionally ephemeral rather than becoming long-term memory.
- **path:** browser-extension → mac-planner → relay-realtime → pendant → dashboard
- **model tier:** Realtime handles the short spoken question and turn-taking; a cheaper background model prepares a compact page capsule and extracts cited regions. Escalate to the stronger model only for multi-section comparison or ambiguous page structure.
- **latency:** Active-tab context should be available within 1 second of a tab-focus/page-change event; spoken answers within 3 seconds for visible text. A tab transition should revoke the capsule immediately, with no background polling after revocation.
- **cost:** Approximately $0.003–$0.02 per question, dominated by sending the selected page region and generating the answer; tab-focus events and capsule revocation are negligible. No public-browser fallback should be used for authenticated content.
- **security:** Page text stays in a short-lived, encrypted context capsule scoped to extension installation, window, tab, and navigation generation. Do not retain passwords, payment fields, hidden DOM, or unrelated tabs; redact likely secrets before model submission. Destroy the capsule on navigation, tab close, explicit “forget,” or a short idle TTL. Answers must cite the visible region and say when the page is no longer available. This is read-only and must never infer permission to click, type, send, or submit.
- **missing:** A browser extension event stream for active-tab focus, navigation generation, close, and visible-region changes; polling command results alone cannot establish when context should be revoked.; A server-side ephemeral page capsule store with strict tab/navigation scoping, redaction, TTL, and an explicit destruction acknowledgement.; A low-latency route that joins pendant voice turns to the current browser capsule without placing the full page into every model prompt.; A compact spoken citation format and dashboard transcript showing which tab and page region supported each answer.

### "“When I double-tap the pendant while text is selected in Safari, save that exact quote with its page title, URL, timestamp, and a short spoken label into a notebook on my Mac.”"
- **useful because:** The owner can currently read a private page, but capturing reliable evidence means manually switching apps, copying text, and recording where it came from. This creates a one-gesture, authenticated-page citation capture useful for research, receipts, policies, and work discussions. It is not a page watch or a drafted transaction: it captures only the owner-selected excerpt, preserving the source while avoiding a copy of the whole private page.
- **path:** pendant → browser-extension → relay-realtime → mac-planner → dashboard
- **model tier:** No expensive realtime reasoning is needed for capture. Firmware sends the gesture; the browser bridge reads the selected range; a cheap model optionally generates a short label only when requested. Realtime can confirm capture with a brief spoken response.
- **latency:** Gesture acknowledgement under 300 ms locally; selected text and metadata saved within 2 seconds. If Safari is unavailable, the pendant stores a tiny pending capture intent and confirms that no quote was taken rather than guessing.
- **cost:** Usually under $0.002 per capture, with almost no model cost unless auto-labeling is enabled. Storage is small: quote, source metadata, hash, and optional label.
- **security:** Only the browser's explicit current selection is transferred; never scrape the rest of the DOM or neighboring tabs. Redact password/payment-like selections and require a second deliberate gesture for unusually long excerpts. Store the citation in the owner's local Mac notebook by default, with encrypted relay transport and a configurable retention period. The result must include a content hash so later edits are detectable.
- **missing:** A browser extension command/event that returns the current selection plus canonical URL, title, tab ID, and navigation generation.; A pendant double-tap gesture event routed to the active browser session, with local debounce and offline intent buffering.; A Mac notebook destination with append-only citation records and a stable schema for quote, source, timestamp, hash, and label.; A receipt linking the physical gesture, selected range, browser tab, and saved file so the owner can audit or delete a capture.


## Changes it proposed to its own stack

### `browser-harness` — Implement a browser-bridge lease/circuit-breaker between /browser/status, /execute, and the existing command queue. Assign each extension installation a reconnect generation and heartbeat lease; when the lease expires, atomically quarantine all pending commands for that device, cancel their 45-second waiters, and materialize a durable job checkpoint (step id, idempotency key, tab/session binding, evidence, and safe-retry classification). On a newer heartbeat, offer/resume only checkpoints whose generation and tab affinity still match; mark old-generation click/type steps stale instead of replaying them. Emit one reconnect-needed event to the Mac planner, pendant relay, and dashboard, with queue age and exact recovery instruction. This is deliberately narrower than the proposed durable runner: it prevents stale-command execution and makes the current queue truthful even before full job persistence exists.
- **owner gets:** The owner stops seeing misleading 45-second browser failures and stops risking duplicate actions after Safari returns. They get one clear message such as “Safari bridge is not polling; 9 commands paused,” and private read tasks continue from the last verified page step when the same session returns.
- effort: Medium: bridge state machine and atomic queue transitions, a small durable checkpoint store, reconnect event wiring, and tests for crash/reconnect/generation mismatch. No new browser extension UI is required beyond heartbeat payload fields.  ·  risk: A false lease expiry could pause harmless work; recover by retaining quarantined commands and allowing explicit retry. A Safari restart may invalidate tab IDs, so read-only navigation can be replanned while click/type actions remain stale. Never delete commands silently; expose quarantine and replay receipts.
- cost: Negligible API cost; roughly one small D1/local JSON checkpoint per command and heartbeat metadata. Avoids wasting relay browser minutes and repeated model retries.  ·  latency: Health failure detected in 10–15 seconds; removes the current 45-second blocking wait. Reconnect resumes on the next heartbeat, typically under 30 seconds.
- security: Improves safety by binding replay to extension generation, device, tab, and session; reduces chance of replaying a stale authenticated mutation. Checkpoint evidence should be minimized/short-retained and page text never sent to the public browser backend.
- depends on: Expose a stable Safari extensionId/device lease and reconnect generation in heartbeat/status.; Reuse existing idempotency keys and receipts from browserBridge/browserSessions rather than creating a second action identity.; Add a small event consumer in mac-planner/relay for reconnect-needed and resumed-job updates.
