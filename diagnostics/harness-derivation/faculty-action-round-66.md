## Capabilities it proposed

### "“From the pendant, gather the things I need to act on from Mail, Calendar, GitHub, and my currently open private browser tabs; turn each into a sourced action card, create any reversible reminders or drafts, and keep working if I walk away.”"
- **useful because:** The owner repeatedly asks to read Gmail, GitHub, and Calendar, but those requests currently fail or require separate surface-specific commands. This is a genuinely cross-body workflow: the pendant captures a short command, relay persists it, the Mac uses granted native AppleScript where browser access is unavailable, the authenticated browser bridge supplies private web context, and the relay returns a concise spoken result plus durable local workbench. It executes reversible follow-up (reminders/drafts) without sending or deleting.
- **path:** pendant → relay-realtime → mac-planner → mac-terminal → browser-extension → unified → faculty-judgement → faculty-action
- **model tier:** Use the realtime tier only to interpret the short spoken command and speak the final 1–2 sentence digest; use a cheaper background model for extraction, deduplication, prioritization, and action-card drafting.
- **latency:** Acknowledge in under 2 seconds, return an initial digest in 15–30 seconds, and continue asynchronously for slow browser sources. The owner can ask for status or completion receipt from the pendant.
- **cost:** Roughly one realtime turn plus 2–4 background extraction turns per invocation; dominant cost is re-sending multi-source context, so pass compact per-item snippets, timestamps, and hashes rather than full pages. Native Mail/Calendar extraction avoids public-web calls.
- **security:** Private mail, calendar, GitHub, and logged-in tabs remain on the Mac/bridge; only minimized snippets and provenance leave for prioritization. Never send mail, submit forms, delete, or purchase. Creating reminders/notes is allowed by owner policy; drafts must be visibly marked unsent. Require explicit confirmation for any irreversible follow-up.
- **missing:** A durable cross-source action-card schema and local workbench writer; Native Mail/Calendar/GitHub adapters using the already-granted AppleScript/macOS surface, with browser fallback; A resumable fan-out/fan-in job that persists source cursors and per-item provenance; A pendant-friendly completion/status packet and audio queue integration

### "“Use my private apps and logged-in sites to complete this task, but don’t send the underlying private text to the cloud—just return the minimum facts and a preview of what would happen.”"
- **useful because:** Today the system can reach separate private surfaces, but it cannot give the owner a trustworthy guarantee that cross-app work is performed with field-level minimization. This would let the owner delegate genuinely sensitive tasks—such as reconciling a calendar commitment with an account form—while keeping raw mail, page contents, and credentials on the Mac/browser. The owner receives only a redacted result and an exact, local before/after preview.
- **path:** pendant → relay-realtime → mac-planner → mac-terminal → browser-extension → unified → faculty-perception → faculty-judgement → faculty-action
- **model tier:** Use a local/background model on the Mac for extraction, joining, and redaction; use realtime only for the short spoken request and final confirmation summary. The cloud model should receive typed facts or hashes, never raw source text.
- **latency:** Acknowledge within 2 seconds; local extraction and preview within 10–20 seconds; long browser work continues asynchronously with a spoken completion receipt.
- **cost:** One small realtime turn plus inexpensive local/background inference. Cloud token cost is substantially lower because only selected fields, confidence, and hashes cross the relay; local storage is a few kilobytes per task plus encrypted audit metadata.
- **security:** The Mac privacy broker must enforce a deny-by-default source/field policy, redact secrets and unrelated text, keep raw artifacts local, and bind every outgoing fact to source, purpose, TTL, and hash. The owner must explicitly approve the minimized payload before any irreversible browser or messaging action; previews remain unsent.
- **missing:** A Mac-local privacy broker that performs source joins and redaction before relay/model access; A typed field-level policy and secret detector covering Mail, Calendar, browser DOM, clipboard, and files; Cryptographic provenance/preview records that prove the proposed action used only approved fields; Relay and pendant protocols for showing the minimized payload summary and requesting confirmation


## Changes it proposed to its own stack

### `integration` — Add a durable cross-surface action-card coordinator between relay, Mac agent, and browser bridge. It accepts one request_id and fan-outs to native AppleScript adapters (Mail, Calendar, Finder/Notes, Messages, Safari/Chrome) plus authenticated browser tabs, normalizes each result into {source, subject, snippet, timestamp, URL/deep-link, confidence, suggested reversible action}, deduplicates by stable hash, writes a local ~/AI-Pendant-Workspace/workbench/<request_id> artifact, and emits progress/completion receipts consumable by the pendant. Each adapter checkpoints independently so a dropped browser bridge or Mac sleep resumes without repeating work.
- **owner gets:** One short pendant request can reliably turn scattered private information into something actionable instead of failing separately on “read gmail,” “read github,” and “read calendar.” The owner gets a spoken digest immediately, a durable reviewable workbench later, and safe reminders/drafts without accidental sends.
- effort: Medium-high: define typed schema and D1/local persistence, implement native AppleScript adapters and browser result normalization, add fan-out/fan-in and retry/idempotency, then connect briefing/audio receipt generation. Test with bridge offline and Mac sleep.  ·  risk: A connector could expose more private text than intended or duplicate an action after retry. Mitigate with source-scoped least-context extraction, stable request/idempotency keys, local-only raw artifacts, redacted relay summaries, and explicit unsent/preview states. If one source fails, report partial completion rather than claiming success; resume from checkpoints.
- cost: No new hardware. One background model pass for normalization/prioritization; cost scales with snippets, not full pages. Storage is small JSON/Markdown artifacts plus hashes; cleanup policy required.  ·  latency: Initial acknowledgement remains realtime; native adapters can return in seconds, browser fan-out in 10–30 seconds. Async receipts prevent blocking voice and allow relay_job_status polling.
- security: Improves security by making provenance and scope explicit, but introduces a central cross-source join. Keep raw private data on Mac, send only selected snippets, enforce source permissions and confirmation on irreversible actions.
- depends on: A typed action-card/workbench schema; Durable job checkpoint storage and resumable fan-out; Native AppleScript adapter allowlist for Mail/Calendar/GitHub/browser; Pendant status/audio queue packet format

### `integration` — Insert a Mac-local privacy broker as the mandatory boundary between native/browser execution and relay/model calls. Adapters return structured fields rather than prose; the broker applies a per-task allowlist, secret/PII classification, purpose and TTL, performs joins locally, computes source hashes and a redacted preview, and emits only the approved projection plus an audit receipt. The relay rejects untyped/raw payloads, while action execution consumes the same approved projection so the preview and the eventual operation are cryptographically linked.
- **owner gets:** The owner can delegate sensitive cross-app work without having to choose between usefulness and exposing entire inboxes, pages, or files. They get a clear proof of what information was used and exactly what will change, while credentials and unrelated private text stay on the Mac.
- effort: High: define field-level schemas and policy evaluation, implement Mail/Calendar/browser/file adapters, add local secret detection and encrypted audit records, enforce relay validation, and test failure/rollback paths across browser and Mac jobs.  ·  risk: Over-redaction may make a task fail; under-redaction could leak sensitive data. Fail closed, explain missing fields locally, allow owner-approved one-time field exceptions, expire projections quickly, and retain only hashes and policy decisions after completion.
- cost: No hardware cost. Small local CPU/storage overhead; lower cloud token cost because raw content is not uploaded. Background model cost is limited to local extraction/redaction and typed-result prioritization.  ·  latency: Adds roughly 0.5–3 seconds for local classification and joining; avoids repeated cloud context transfer and can make total sensitive tasks faster. Long jobs remain asynchronous.
- security: Materially improves confidentiality and auditability. The broker becomes a high-value local component and must be sandboxed, encrypted at rest, authenticated to the relay, and prevented from silently widening policy scope.
- depends on: A typed field-level privacy policy/schema; Mac-local adapter and secret-classification service; Relay schema validation that rejects raw untyped private payloads; Preview/receipt linkage and owner confirmation protocol
